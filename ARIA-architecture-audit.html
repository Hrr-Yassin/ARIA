Verdict

ARIA today is a well-guarded, human-supervised research workbench. It is not yet an autonomous, 24/7 vulnerability-finding platform. Its safety plumbing (scope gate, single-use approvals, isolated worker, no-replay recovery) is real and unusually careful. What is missing is the part that finds and proves bugs on its own: the autonomous loop only establishes reachability, the bug-bounty execution envelope is curl GET/HEAD, verification is human-recorded and covers one bug class, and nothing schedules, resumes, scales or monitors work.

What it does today. An operator imports a program policy, reviews and activates it; an engagement may then run bounded HTTP observations through a shared authorization gate and a Docker worker. Specialist agents analyze saved evidence on demand (orchestrator/team_coordinator.py:1), a human records validation, and reports are drafted and signed off by a human. The README itself says full autonomous research and production readiness “have not been established” (README.md:29-32). This audit confirms that against the code.

Facts, absences and assumptions

Verified in code

  • Authorization is claimed (marked consumed) before the worker is contacted, so a timeout cannot replay a command (memory/execution_authorization.py:188-191).
  • Worker containers are read-only, cap-dropped, memory/pid-limited, with an nft egress allow-list and DNS pinned at creation (worker/runtime.py:71-93, worker/policy.py:113-124).
  • Restart cancels active jobs and blocks runs instead of resuming (worker/service.py:197-201, memory/autonomous_runs.py:33-44).
  • Evidence is hash-snapshotted; stale evidence blocks advancement (memory/finding_verification.py:119-147).

Verified absences (searched)

  • No Prometheus/OpenTelemetry/Sentry/alerting code.
  • No Celery/ARQ/APScheduler/Temporal or any scheduler.
  • No HackerOne/Bugcrowd/Intigriti integration.
  • No lint, type-check, SAST, dependency-audit or image-scan step in .github/workflows/ci.yml.

Unverified / assumptions

  • I did not run tests; I did not see CI results (the GitHub API rate-limited the lookup).
  • No live-model quality, precision/recall, cost or latency data exists in the repo (docs/aria-product-roadmap.md:198-210, Phase 7 unchecked).
  • memory/professional_reports.py, memory/parsers.py, config/cve_enricher.py, llm/engagement_budget.py, the Burp Java extension and the web UI were skimmed or taken from docs/tests only.
  • Roadmap durations and the 0–5 scores are my judgment.

Method and limits

Shallow clone of the branch, then static reading only: no dependency installation, no code execution, no scans, no contact with any target. Read in depth: orchestrator/*, worker/*, memory/{execution_authorization,finding_verification,autonomous_runs,program_policy,application_map(outline)}, agents/{autonomous_engine,vuln_agent,recon_agent}, api/main.py, api/routers/{team,programs}, security/program_fetch.py, llm/pool_manager.py, CI, deploy unit and the README/roadmap/status docs. The repository’s own documents were treated as claims to check, not as evidence. Line numbers refer to commit edbefe5.
